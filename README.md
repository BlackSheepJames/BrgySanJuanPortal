# San Juan Barangay Management System

A local-network barangay records workspace built for XAMPP, PHP, and MySQL/MariaDB.

## Install

1. Start **Apache** and **MySQL** in the XAMPP Control Panel.
2. Import `schema.sql` into MySQL using phpMyAdmin or the MySQL command line.
3. Create the first administrator account directly in the `users` table, using a password hash generated by PHP's `password_hash()` function.
4. Open `http://localhost/brgySanJuan/` to use the service landing page, then sign in at **Staff and resident sign in**.
5. Add barangay staff accounts under **Staff access**. Give each person their own account and the least access they need. Residents can create an account from the sign-in page; public registration always assigns **Barangay Residents** and creates a linked resident profile. Manage accounts and role changes at `/brgySanJuan/systemadmin/`.

The database connection is configured in `config.php`. The default settings match a typical local XAMPP install (`root`, no password). Change them if your MySQL account differs. The web app does not create the database or the initial administrator account.

The app automatically upgrades the earlier account schema when it opens, adding email/phone fields, the new roles, the resident-account link, and the announcements table while preserving existing accounts. `schema.sql` contains the same structure for new installations. After sign-in, users go to a role-specific dashboard at `/systemadmin/`, `/barangaycaptain/`, `/secretary/`, `/healthworker/`, `/tanod/`, `/alsteacher/`, or `/barangayresidents/`. Users can sign in with either their username or personal Gmail address. Resident registration requires a `@gmail.com` email, a 7–15 digit phone number, and a password of at least 8 characters with an uppercase letter, a number, and a symbol. New registrations create resident profiles; only the System Admin can assign roles through the account dashboard. Staff roles can post shared community calendar announcements; residents can view them.

## Modules

- Resident profiles, household codes, demographics, voter status, sector classifications, and address history
- Barangay document requests and releases with OR number and fee tracking; printable certificates have a QR verification link
- Katarungang Pambarangay cases, hearing schedules, mediation status, and generated Certificate to File Action numbers on referral
- Evacuee family check-in, live shelter occupancy, and optional OpenStreetMap links from shelter coordinates
- Household relief distribution with duplicate household/package protection and recipient sign-off
- Health service logs, medicine stock and reorder thresholds, and financial aid sign-off
- Role based staff access and an append-only application activity log

## Backups

Run `backup.ps1` from PowerShell to create a dated SQL backup outside the public web folder (default: `C:\xampp\backups\brgySanJuan`). Edit the paths at the top if XAMPP is installed elsewhere. Schedule the script with Windows Task Scheduler for a daily local backup. To keep a second copy, configure your approved encrypted backup or cloud sync product to copy that backup folder; do not put backup files under `htdocs`.

To restore, stop application activity, then import the chosen SQL file into MySQL using phpMyAdmin or `mysql`. Keep more than one dated backup and periodically confirm that a backup can be restored.

## Local network and privacy

The system stores records in the barangay's MySQL database. Access roles and an activity log are enforced by the application; health records have narrower access. Use individual accounts, protect the XAMPP host, and use HTTPS before allowing access across a network. Enable full disk encryption on the computer or storage that holds MySQL data and backups. The app is a technical starting point and does not itself establish compliance with the Data Privacy Act or barangay retention and disclosure rules. Configure those policies with the barangay's privacy officer before using real resident data.

QR verification, the web fonts, and map links use external services; printing a QR code or opening a map requires internet access. Certificates still display their verification URL if the QR library is unavailable.
